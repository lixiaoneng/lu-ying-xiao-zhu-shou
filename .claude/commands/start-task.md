请执行安全任务启动流程。在用户明确确认前，不要修改任何代码。

## 步骤

1. 读取以下文件（必须读，不跳过）：
   - CLAUDE.md（完整读取，特别是"生产安全铁律"和"禁止事项清单"）
   - PROJECT_STATUS.md（已完成能力、当前安全约束、下一步任务）

2. 运行以下命令：
   - `git branch --show-current`（确认当前在 dev 分支）
   - `git status --short`（确认工作区干净或了解未提交的改动）
   - `git log --oneline -5`（了解最近 5 次改动）

3. 输出任务启动报告，格式如下：

```
## 任务启动确认

### 当前状态
- **分支**：[branch]（应为 dev）
- **工作区**：[干净 / 有未提交改动: 列出文件]
- **最新 commit**：[hash] [message]

### 本次任务目标
[用 1-3 句话复述用户要做的事]

### 计划修改的文件
- [文件 1]：[改动内容概述]
- [文件 2]：[改动内容概述]
（如果还不确定，说明需要先读哪些文件）

### 绝对不会修改的文件
- sync.ts / store.ts（云同步 + 数据层）
- PlanDetail.tsx / tabs/*（计划功能）
- plans 表（数据库）
- [其他本次任务无关的文件]

### 风险提示
[列出本次任务的主要风险点，如有]

### 数据库改动
[是 / 否。如有，必须先出 SQL 方案，确认后执行]

---
⚠️ 以上是任务计划，**还没有改任何代码**。

请确认：
1. 任务目标是否正确？
2. 修改文件范围是否合理？
3. 是否有我遗漏的约束？

确认后我立即开始开发。
```

## 注意

- 在用户回复"确认"或等效肯定之前，不要修改任何文件
- 如果当前不在 dev 分支，必须先提示，不要直接 checkout
- 如果工作区有未提交的改动，提示用户决定是否先 commit
- 如果任务涉及数据库操作，必须在报告中单独列出 SQL 方案等待确认
- 如果任务涉及修改 plans 表或 RLS，必须明确拒绝并说明原因
